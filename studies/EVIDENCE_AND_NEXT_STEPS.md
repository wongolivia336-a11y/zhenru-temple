# 真如寺建筑构件精度研究 · 实施边界

## 本轮是什么

- 生成一套真正有曲面、断面和厚度的斗栱/瓦件 GLB 样板，而非二维参考图片。
- `generate_assets.py` 是可修改和再生的参数化源码，输入均为米。
- `blender_import_and_save.py` 是 Blender 导入/生成 `.blend` 的脚本；本交付环境没有 Blender，故 **没有伪造 .blend 源文件或宣称已经在 Blender 中验证**。
- `detail-lab.html` 是独立交互查看页：环绕、缩放、构件分解、线框、自动旋转、移动端触摸（依赖 Three.js CDN）。
- GLB 均已通过 `trimesh.load` 解析、网格统计与结构检查；尚待在目标浏览器中做 WebGL 交互验收。

## 当前几何约束

- 斗栱：独立部件、非矩形栱端、斜昂、承托斗、柱头片段，真实有厚度的封闭网格；出跳尺寸均为研究赋值。
- 屋面：独立板瓦和筒瓦；每片是厚壳而非单面材质；按横纵方向生成规律搭接。采用公众来源所述约26°缓坡。该瓦面只是**局部屋面 patch**，不是完整歇山顶。
- 本轮没有复刻真如寺的具体斗栱铺作序列、榫卯、檐角、脊饰、瓦头纹样、现存旧木形变或修缮痕迹。
- 图像中的自然木色与瓦色是可视化风格，不是从现场采样的物理颜色。

## 与原仓库合并的实施顺序

当前上游：https://github.com/wongolivia336-a11y/zhenru-temple/tree/feat/zhenru-archive-final-handoff

1. 先把 `assets/*.glb`、`detail-lab.html` 与 Python 源码作为独立 `detail-study/` 目录纳入仓库。
2. 使用 HTTP 本地服务验证样板切换、OrbitControls、触摸、导出、wireframe、拆解、屏幕适配和浏览器控制台。
3. 建立 `assetRegistry`：`partId`, `parentId`, `stageId`, `evidenceGrade`, `sourceUrls`, `localTransform`，避免依赖网格名称字符串查找。
4. 用专门的 GLTFLoader 装载器把研究样板挂到原项目的 3D 场景下，支持切换 `currentLowFidelity` / `studyHighFidelity` 的对照模式。**不要直接覆盖**现有历史时间轴；它的几何逻辑仍需逐级校核。
5. 根据实测/多角度照片重建柱头、补间、转角铺作，完成三种相互区分的真实构件套件，再开始完整屋顶。
6. 完成真实歇山前后坡和四角翼角，再迁移瓦件实例化。要求通过 Blender 与浏览器视觉回归、性能阈值后才能替换主模型。
7. 先获得可核验的梁架/修缮图档，再进行内部明草构架重建。

## 用户可以帮助提供的资料（按价值排序）

1. 1963–64 年真如寺大殿落架大修的测绘图、平立剖、梁架详图、斗栱节点图或相关文献截图。
2. 自己拍摄的建筑正立面、山面、前后檐、斗栱、瓦口和室内梁架的多角度原图，最好有拍摄视角说明。
3. 一张清晰可辨的尺度参照（卷尺、檐柱直径或已知柱距），帮助把几何从观感提升为有尺度依据。
4. 对最终用途的确认：网页交互展示 / HCI 学术汇报 / 文物研究推演，对证据强度与性能预算要求不同。

若暂时没有上述材料，仍然可以继续做**高完成度研究性视觉样板**，但不应声称为高精度历史还原。
