# V10 · 真如寺「进入寺院 / Enter Temple」交付与设计边界

**源代码 PR**：https://github.com/wongolivia336-a11y/zhenru-temple/pull/16  
**设计选择**：感受进入理解 / 第一人称 / 真实建筑+克制的艺术指导 / 自愿共在 / 短暂痕迹。  
**状态**：第一版端到端可运行的**独处参访**；多人代码具备客户端和服务端，但尚需单独部署持续在线 WebSocket 服务，不能谎称已上线多人功能。

## 体验流程

1. 从原建筑档案主页点 **「进入寺院」**。进入时自动切换到现状研究阶段，隐藏时间轴、研究按钮、构件热点，保留清晰的「返回建筑档案」路径。
2. 第一人称视线高度约 1.72m；鼠标或触屏拖动转头、WASD 移动、手机可用现有方向控制。入口、檐下、殿内为可跳转空间锚点，不强制用户学游戏键位。
3. 进入庭院的真实 Three.js 空间，使用 **InstancedMesh** 铺装石径与低饱和地面；人行路线仅是概念性参访动线，不是现状测绘。殿堂和古银杏沿用既有研究模型。
4. 走近檐下才出现 **「留意这处斗栱」** 和 **「查看构件研究」**。前者创建有衰减生命周期的 Three.js 空间圆圈（约 85 秒）；后者带用户回档案，并展示斗栱的证据限制说明。这是「从感受进入理解」的真正交互转折。
5. 参访默认**独处**，不发送位置。匿名共在没有服务端时按钮明确不可用，也绝不生成假在线访客。
6. 环境风声通过按钮主动打开，Web Audio 生成、低音量，不是现场录音，切换标签页或离开参访即关闭。
7. 原 V9 建筑档案、时间轴、参考研究、原形制、下载 GLB 不受影响。

## 技术与多人的真实开通方式

**前端**：静态 Three.js ES modules，新增 `reconstruction/visit-courtyard.js`、`reconstruction/visitor-figures.js`、`presence/client.js`、`presence/config.js`、`audio/quiet-air.js`。无需替换框架。

**可选实时后端**：`server/presence-server.mjs`（Node 20+ + ws）。部署在能保持 WebSocket 长连接的服务（如持久容器）；Vercel 静态站点不承诺提供驻留 WebSocket Server。

后端部署示例（需提前选择持久 Node 服务并完成运维策略）：

```sh
cd server
npm install
ALLOWED_ORIGIN=https://zhenru-temple.vercel.app PORT=8080 npm start
```

为服务器配置 TLS/WSS 反向代理、健康监测及合规访问控制，然后在 `presence/config.js` 中填入经过确认的 `wss://YOUR-HOST`。未填时保持默认私密。新服务部署**不在本轮完成范围**，需要实际的服务器和域名资源。

共在只在用户主动点 **「进入共在」** 后建立连接：通过随机匿名临时 ID 同步坐标和朝向，不收用户名、国家、聊天或个人资料；每房间约 14 个其他访客上限，位置消息限速；切换回独处或离开立即发送断开。真实化身采用中性人体比例、低细节，不用僧袍、不用国旗；只有服务器确认的实际 peers 才生成。主动留下的注意力痕迹只同步构件类型，约 85 秒后销毁，默认不存数据库、不留长久档案。

**后续真要公开运营的风险**：服务器可能有主机层网络访问日志，不能宣称匿名等于绝对不可追踪；需做连接频率控制、区域容量、反滥用、异地延迟、网络恢复、隐私说明、与寺方沟通；不能将宗教礼仪做成积分排行。

## 文博真实性声明

- 主体仍是研究性建筑模型，不是实测复原；1290/1320 时期环境及银杏位置没有充分测绘资料。
- 新铺装只是提高空间感的**概念性石径**，不能当作真如寺真实铺地、真实路宽或游线；本轮没有凭空添加被当作史实的佛像。
- 殿内佛像依然是待核验的空间占位，不是经认证的造像重建。视觉写实不等于史实准确。
- 不模仿佛教仪式的回报、收集功德或强制角色扮演。跨国文化访客可只参与建筑观察。
