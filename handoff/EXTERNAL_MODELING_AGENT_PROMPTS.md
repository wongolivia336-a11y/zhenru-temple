# 真如寺大雄宝殿｜三维建模外部 Agent 交接包

## 目的

把当前程序化几何中最需要专业建模的部分拆成可独立委派的任务。请将本文中每个“可复制提示词”单独交给对应的 Blender / 3D 建模 / 代码 Agent。

**项目**：https://github.com/wongolivia336-a11y/zhenru-temple  
**审阅入口**：PR #4 https://github.com/wongolivia336-a11y/zhenru-temple/pull/4  
**工作分支**：`codex/zhenru-visual-redesign`

先阅读 `README.md`、`sources.md`、`handoff/`，再检查 `hall-model.js`、`assets/hall-eaves.jpg`、`assets/temple-interior.jpg` 和 `qa/final-desktop-1440.png`。截图是交互原型，不是测绘图。每个任务必须在独立分支或独立资产目录工作，不要覆盖现有模型。

## 当前模型缺口与委派顺序

| 优先级 | 建模任务 | 目前的不足 | 最合适的执行方式 |
|---|---|---|---|
| P0 | 大殿主体与屋顶 | 现有屋面、檐口和脊线为程序化近似；无法代表精确测绘形态 | Blender 手工/参数化建模，使用实测尺寸与多角度照片校准 |
| P0 | 梁架、斗栱与柱网 | 目前更多是整体视觉提示，构件连接和受力层级不足；分解也不是逐构件检查 | 先建一个有来源依据的典型开间，再扩展成可装配构件系统 |
| P0 | 历史阶段模型 | 时间轴目前不能代替每个阶段各自有依据的几何版本 | 建独立分期根节点与差异清单；每项都要有来源及证据等级 |
| P1 | 室内与佛像 | 当前室内照片偏暗，不能可靠判断佛像尺寸、造像细节、梁架或空间深度 | 先向寺方申请多视角摄影/测绘；资料不足时保留占位，不生成“想象中的真像” |
| P1 | 现状照片级模型 | 当前素材不够覆盖外部与室内，无法从两张照片还原完整建筑 | 获准后采集多视角照片；摄影测量网格与 Gaussian Splat 分开制作 |
| P1 | Web 模型整合 | 需要在 Three.js 中保留构件命名、阶段切换、热点、室内漫游和性能 | 单独交给 Three.js/GLTF 工程 Agent，接收通过检查的 GLB |

## 选择 AI 工具的边界

- **核心建筑几何**：优先交给会用 Blender 的建筑/数字遗产建模者，或能写 Blender Python 参数化脚本的代码 Agent。AI 生成器不应根据单张照片猜整座殿的尺寸、背面和隐藏结构。
- **单体草模与纹理测试**：可试 [Meshy Image-to-3D](https://docs.meshy.ai/en/api/image-to-3d)、[Tripo Image-to-3D](https://www.tripo3d.ai/features/image-to-3d-model)、[Hyper3D Rodin](https://hyper3d.ai/help/articles/what-features-does-hyper3d-have)。它们能从图像生成网格并导出常见三维格式；适合生成局部候选形体，再由人检查和重拓扑，不适合作为有测绘精度承诺的建筑复原。
- **本地开源图像转模型**：可试 [Tencent Hunyuan3D-2](https://github.com/Tencent-Hunyuan/Hunyuan3D-2)，项目公开了图像转形体、纹理和多视图工作流，并支持输出网格。部署前核对硬件要求与当前模型许可条款：[官方 License](https://github.com/Tencent-Hunyuan/Hunyuan3D-2/blob/main/LICENSE)。
- **现状摄影测量**：照片覆盖充分后，用 [Meshroom](https://github.com/alicevision/Meshroom) 或 [COLMAP](https://github.com/colmap/colmap) 建现状网格；用 [Nerfstudio Splatfacto](https://docs.nerf.studio/nerfology/methods/splat.html) 训练照片级漫游层，再由 [Spark](https://github.com/sparkjsdev/spark) 接入 Three.js。Splat 是现状视觉层，不能替代可测量、可拆解的木构模型。
- **证据底线**：AI 输出属于候选资产。未经照片、尺寸或档案复核，不得标为“真如寺精确复原”。

## Prompt 3｜元代、清代、近现代修缮、当代的几何分期

~~~text
你是建筑史研究者与数字建模协作者。请将真如寺大雄宝殿的时间轴做成真正不同的、有来源的几何状态，而不是给同一模型换颜色。

项目：https://github.com/wongolivia336-a11y/zhenru-temple
先逐条核对 sources.md、handoff/、项目已有阶段文字和 PR #4。时间标签（元代初建、清代改建、1963–64 修缮、当代）是待核对的研究框架；不得把标签本身当作该阶段建筑形制的证据。

任务：
1. 建一张“事件—构件变化—来源—证据等级—模型表现”对照表。
2. 对每一时期列出可以证实的结构状态、不能证实的部分和相互冲突的记载。
3. 仅对有来源支持的构件差异制作几何版本；例如双檐/外扩柱列如属推定，必须作为独立可开关的研究假说，不可与史实混写。
4. 每个时期使用独立根节点或可追溯的差异层，保证时间轴滑动时确实改变建筑构件，而非只改变材质。

- stages.json：时期、日期范围、事件说明、可见构件差异、来源 URL/页码、证据等级、置信说明；

验收：
- 时间轴上的每个几何变化都能追溯到来源；
- 推定构件默认不伪装成确定史实，UI 能显示“研究推定”；
- 1963–64 与当代的差异必须有修缮记录、照片或明确来源支撑；没有资料就明确报告缺口，不造版本。
~~~

## 建议执行顺序

1. 先让 Prompt 1 和 Prompt 2 的建模 Agent 只做一个屋面样本与一个木构典型节点，先审核风格、证据和工程格式。
2. 与寺方联系，申请大殿现状测绘、历次修缮图纸/照片和室内拍摄许可；资料到位后再启动 Prompt 3、4、5。
3. 最后让 Prompt 6 接收审核过的 GLB；先做模型验收，再合入 Web 时间轴。
4. 单图 AI 生成适合探索屋瓦端头、灯具或非关键装饰的候选，不应承担“整殿复原”。若没有测量资料，最专业的交付就是列清不确定项并暂停该部分，而不是让模型猜完整。
