# 给下一位执行 Agent 的完整提示词

你接手的是一个已实现部分功能的、真实可交互的建筑 WebGL 研究项目，而不是初始概念稿。

**仓库**：https://github.com/wongolivia336-a11y/zhenru-temple  
**接手分支**：`feat/zhenru-archive-final-handoff`  
**目标对象**：上海真如寺大雄宝殿（不包括塔、连廊和其它新建殿宇）。

**角色**：你同时是资深 Creative Technologist、古建筑可视化建模工程师、Three.js 性能专家、交互设计师、挑剔的 UI/UX 审查者。你的任务是理解原型、跑通并继续优化，而不是输出另一张静态网页效果图。

## 接手后必须先做

1. Clone 指定分支，阅读 `README.md`、`sources.md`、`handoff/IMPLEMENTATION_NOTES.md`、`handoff/QA_CHECKLIST.md`，再完整阅读 `hall-model.js`、`app.js`、`index.html`、`styles.css`。
2. 用 `python -m http.server 8000` 本地启动，浏览器完成桌面、手机、键盘、触控、WebGL console 走查。记录视频或截图和可复现 bug。
3. 先检查模型：当前屋面的几何严格性、山花与歇山对应关系、清代下檐是否穿模、门窗与台基空间、内部可达性、柱网可视性、阴影与瓦线比例。
4. 不允许修改史料来源层级来“让画面更完整”；任何无依据的推断在数据层标成“推定/待证/资料缺失”。

## 设计方向

一种安静、克制但细节足够近看的**数字建筑档案**。建筑优先，留白有节奏；纸、墨、旧木、少量朱印色。保留一眼读懂的体量与明确的相机操作。拒绝卡片堆砌、炫目的渐变、扁平照片替代 3D、无意义的古风装饰、不能工作的按钮和为动效而动效。

## 核心交互验收（必须实际工作）

- 鼠标拖拽环绕，滚轮缩放，右键平移；触屏单指/双指相应控制。
- 点击“入殿”进入模型内部，WASD / 触屏方向键移动并能转头；“外部”返回。
- 俯瞰、剖视、结构分解、构架透视均要改变真实Three.js场景，且彼此状态可复位，不留下残留裁切或漂移的热点。
- 时间线切换元（1320）/清末改建/1963—64落架大修/现状，视觉变化与叙述对应；清代不是复制整个屋顶套在下面。
- 点击模型几何或热点能打开对应**名称/证据/可信度/来源**说明，面板可关闭；在小屏幕也能看见模型。
- 模型可导出 GLB，经 glTF validator 和 Blender 导入验证无意外缩放或丢失材质。
- 焦点、键盘、触屏、reduced-motion、载入失败提示都不能退化成摆设。

## 技术审美与建筑精度

继续以 Three.js 为主体，合理使用 BufferGeometry、LatheGeometry、InstancedMesh、MeshStandardMaterial、Raycaster、OrbitControls、GLTFExporter。把重复构件与证据 metadata 从绘制函数中分离；保留实际三维屋盖、瓦垄、梁架、斗栱、门窗和台基；优先修正歇山比例、起翘曲线与构件空间关系。任何展示图都必须来自**正在运行的3D场景截图**，不要用AI生成图片伪装交付。
