# 第五轮：按照片/公开资料校准真如寺屋顶坡度

日期：2026-11-08。研究对象严格限定真如寺大殿本体，外院其它新建建筑、佛塔不纳入测量目标。

## 为什么不是继续增加瓦片
旧版本原始研究几何的跨度为 17.25 m，屋面中央檐口约 6.72（模型坐标），屋脊 9.55。只用这三个假设值计算，平均坡角：
`atan((9.55 - 6.72)/(17.25/2)) = 18.1655°`。
2025 年上海普陀区政府的介绍 [《探秘大殿的建筑密码》](https://www.shpt.gov.cn/tupianxinwen/20250416/958655.html)提到现状屋面约 26°。另有文章也出现“14米高”说法，但没有完整剖面测绘图；**本轮不直接强行把总高写成 14 米**，避免假精确。

## 几何约束及公式
- 既有屋面跨度研究值：17.25 m（它不是寺方测得的檐口尺寸；平面殿身面阔约 13.4m，进深约 13m）。
- 檐口基准高度：6.72（模型原有的相对坐标，不等同于实测绝对高程）。
- 新研究屋脊高度：`6.72 + tan(26°) × (17.25 / 2) = 10.9267`。与旧 9.55 的差为约 1.38m。
- 内部屋架同步作比例放大，但固定屋架檐口的原基准 6.16：
  `scaleY = (newRidgeY - 6.16)/(9.55 - 6.16) ≈ 1.4061`;
  `positionY = 6.16 × (1 - scaleY)`。
- 这是**模型参数研究**，不是榫卯结构力学复原；若要严谨，需要断面、实测的檐口高程、举架与屋顶跨度。

## 可交互校准台
浏览器打开 `reconstruction/reference-review.html`：
- 左边公开在仓库内的自有参考照片，支持本地选择用户拍摄照片，不会上传；
- 右侧是真实 Three.js 模型，能旋转、进入、拆解；
- 18°–34° 的研究参数，默认26°，按“应用到模型”刷新并实际重新生成三维几何；
- 输出 JSON：包含实际应用的坡度、来源链接、人工复核勾选和待修改项；始终标记 PENDING，不能自己在无人核查时宣称通过。

## img2threejs 分阶段工作需要补充的证据
1. 外檐、侧立面、正立面**同一相机标定视角**截图（原始照片 EXIF、内外参、透视关系）。
2. 测量/比对：正脊线、山花转折点、四角檐口及瓦垄中线。
3. 先调宏观屋面轮廓，再调瓦件与斗栱。没有构件测绘不得推断具体榫卯。
4. 如果使用几何外的公开摄影，遵循来源和许可，不把网上社交媒体图当作免费训练数据。

## 已能自动验证 / 还未能验证
`node scripts/check-roof-parameters.mjs`：名义坡角、三角函数关系、屋架基准点、不合法URL入参、18–34范围。
`node scripts/check-model-fidelity.mjs`：源码与参数链接及既有结构 gate。
仍待：用户照片与当前网页截图同机位比较、真实浏览器动态坡度切换、手机帧率/温升、实测结构精度。

## 自动化实际 WebGL 几何测试
`scripts/browser-smoke.mjs` 在 GitHub Actions 的 Chromium/SwiftShader 中加载本地 HTTP 站点，18° / 26° / 34° 分别触发真实 3D 场景重新载入，从 `window.__zhenruQA.getRoofCalibration()` 读取屋顶世界包围盒，验证不是仅修改数值标签。还检查剖视、分层拆解、重置、390px 溢出及保存截图。此检查不证明摄影测量精确度或实机 GPU 性能。运行状态需要查看该分支最新 Actions。
